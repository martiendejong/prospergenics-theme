# Prospergenics website audit: old and new theme

Date: 2026-10-23. Scope:

- **Old site (production)**: the theme on `master`.
- **New site (test)**: the `prospergenics-2026` theme and the static `/people/`, `/experts/` and `/community/` pages from `design/new-hero-2026-10`.

## How this was tested, and its limits

The cloud environment this audit ran in can't reach `prospergenics.com`, `test.` or `listings.` (blocked by its network policy). So both themes were installed on a **local WordPress 6.8.3** with representative content:

- Pages crawled with Playwright at 1440 px and 390 px, with axe-core (WCAG 2.1 AA) on every page.
- Lighthouse 12 (simulated mobile 4G) on the key pages.
- Route and status-code checks, header checks, and a manual code review.

**Not verified, because it needs the live sites:**

- Real content and plugins (Yoast, SEO God, jengo-listings, SMTP mu-plugin).
- Cloudflare/WAF and TLS.
- Whether mail actually gets delivered.
- Site Health and the pending updates.
- The legacy redirect map and the real sitemap.

Production `functions.php` has also drifted from git (task 797's meta description and an SMTP block), so live output may differ slightly from what is described here. Section 5 lists the live checks still to do.

## 2. What works (keep it)

**Old theme**
- Mature SEO layer:
  - Title override that beats Yoast.
  - One de-duplicated set of OG/Twitter tags.
  - Organization, Person and Course JSON-LD.
  - Dutch hreflang page.
  - 301s for `/kenya/` → `/about/` and `/team_member/*` → `/members/*`.
  - Correct canonicals and a real 404 status.
- Security basics: `security.txt` (RFC 9116), plus X-Frame-Options, X-Content-Type-Options, CSP and HSTS.
- Accessible structure: skip link, header/nav/main/footer landmarks, a mobile menu button, one `h1` per page. Accessibility score 96.
- The contact form uses a nonce, sanitised inputs and escaped output.
- 10 regression test files in `tests/`.

**New theme**
- A strong, modern visual identity. "You create value" is a clear message over a real team photo, with a consistent palette and type system across all pages.
- Good interaction work: reduced-motion is respected, CLS is 0, and homepage TBT is only 120 ms.
- About page scores 100 for accessibility and 100 for best practices.
- The value test is a well-designed lead flow: an email confirmation gate stops abuse, and the AI result is inserted with `textContent`, so it's XSS-safe.
- People and list pages carry `Person` and `ItemList` JSON-LD and meta descriptions.
- Templates call `wp_head()`/`wp_footer()` on the front page and About, so plugins can hook in there.

### Medium

- **Accessibility**: **Fixed in PR #23** (homepage Lighthouse accessibility 100; the empty alts were checked and are correct).
  - Colour-contrast failures: 8 elements on the old home, 1 on the new home.
  - `nested-interactive`: the chat orb is a clickable element with a button inside.
  - Heading order skips levels on the new home.
  - `label-content-name-mismatch`: the `aria-label` doesn't match the visible text.
  - 9 decorative-looking images have empty `alt`. Check which ones carry meaning.
- **CSP is very permissive** (`unsafe-inline`, `unsafe-eval`, any `https:`). It also blocks WordPress's emoji `blob:` worker, which puts a console error on every page of the old theme. Fix by tightening it to the real origins and adding `worker-src 'self' blob:`. `Referrer-Policy` and `Permissions-Policy` are missing. **Partly fixed in PR #23:** blob: worker allowed, Referrer-Policy and Permissions-Policy added, strict policy shipped as Report-Only to check on test before enforcing.
- **Google Fonts**: 3 families and 11 weights, loaded render-blocking from Google. That's slower, and loading them from Google is a GDPR problem for EU visitors. Self-host 2 families and 4–5 weights. **Fixed in PR #23:** self-hosted from assets/fonts/.
- **WordPress information exposure** (default WP; Cloudflare may already block some of it): **Fixed in PR #23** at theme level: XML-RPC refused, generator removed, users endpoint and author archives hidden from visitors. `X-Powered-By` is removed where PHP allows.
  - `/wp-json/wp/v2/users` and `/?author=1` reveal admin usernames.
  - `xmlrpc.php` answers.
  - A `generator` meta tag gives the WP version.
  - `X-Powered-By` gives the PHP version.
- **The About page is `noindex`.** That's correct on test, but it must be removed when it goes to production.
- **People pages**: no canonical or OG, and they live outside WordPress (see the completion plan, F4). A fixed 620 px decorative circle sits in the person-page hero; it's clipped, but worth checking on small screens. **Partly fixed in PR #24:** canonical and sharing tags, the same header/menu/footer as the rest of the site, and listed in the sitemaps. Still not editable in wp-admin (decision on CPT vs jengo-listings pending).
- **Duplicate `lang` attribute** in the 2026 templates (`lang="en"` plus `language_attributes()`): the first one wins, so `en-US` is ignored.

## 4. Old and new side by side

| Area | Old (production) | New (test) |
|---|---|---|
| Visual design / brand | Dated, generic sections | **Strong, modern** |
| Navigation and footer | ✅ | ❌ (C5) |
| Routing: pages, blog, 404 | ✅ | ❌ (C1) |
| SEO metadata and schema | ✅ mostly (meta description only as live drift) | ❌ (C2) |
| Security headers / security.txt | ✅ (CSP too loose) | ❌ (C2) |
| Performance | ❌ slow (4.9 MB) | ❌ very slow (13.9 MB) |
| Accessibility | ✅ 96 | ⚠ 93 (missing landmarks) |
| Lead capture | ⚠ form, unreliable | ⚠ value test + chat, no consent notice, placeholder WhatsApp |
| Profiles | WP CPT `/members/` | Static `/people/`, CSS broken (C3) |

Conclusion: the new design's look and interaction are the way forward, but its WordPress layer is a prototype. The fastest path to launch is to keep the 2026 front end and bring across the old theme's routing, templates, SEO and security code.
